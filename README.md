# Реляционная Экосистема Workspace (Vanilla JS & Go)

Высокопроизводительное Offline-First веб-приложение на чистом JavaScript (ООП / SOLID) с бэкендом на Go. Пространство позволяет проектировать реляционные метамодели данных любой сложности (аналог Airtable/Notion), поддерживая внутреннюю иерархию (Дерево), одиночные ссылки (`RELATION`) и встроенные контекстные подтаблицы (Master-Detail) двух типов.

---

## 🗺️ Карта поддерживаемых связей

1. **Внутреннее Дерево (`parentId`)**: Иерархия строк «папки внутри папок» в рамках одной таблицы.
2. **Поле-Ссылка (`RELATION`)**: Одиночный выпадающий список для связи строки с конкретным элементом другой таблицы.
3. **Вложенные подтаблицы (Master-Detail)**: Контекстные вкладки внутри карточки элемента, работающие в двух режимах проектирования:
   - **🔒 Подчиненный (1:N)**: Эксклюзивное владение. Строка дочерней таблицы принадлежит только одной карточке.
   - **🔗 Общий пул (N:M)**: Совместное владение. Строка общая и может быть привязана к нескольким карточкам сразу.

---

## 💼 Комплексный бизнес-пример настройки связей

Смоделируем рабочую среду из трех справочников:
1. **Проекты** (Главный справочник верхнего уровня).
2. **Клиенты / Контрагенты** (Связан с Проектами в режиме **Многие ко многим**, так как один Клиент может участвовать в разных Проектах, а в одном Проекте может быть задействовано много Клиентов).
3. **Договоры** (Строго подчинен Контактам в режиме **Владелец-Подчиненный (1:N)**, так как конкретный договор заключается эксклюзивно с одним клиентом).

### 🗄️ Как это выглядит в базе данных (IndexedDB / JSON Backup)

Ниже представлены реальные структуры объектов (слепки), хранящиеся в базе данных для каждого справочника. Связи Master-Detail инкапсулированы в системном поле `_ownerContext`.

#### 1. Справочник «Проекты» (ID: 101)
Обычный независимый справочник. В его метаданных через кнопку `⚙️ Связи` указано, что к его карточкам прикреплен справочник Клиентов (ID: 102) в режиме совместного пула (`MANY_TO_MANY`).

```json
{
  "id": 101,
  "type": "directory",
  "title": "Проекты",
  "columns": ["Наименование", "Бюджет"],
  "columnTypes": { "Наименование": "TEXT", "Бюджет": "NUMBER" },
  "allowedSubDirectories": [
    { "childDirectoryId": 102, "relationType": "MANY_TO_MANY" }
  ],
  "rows": [
    { "id": "proj-alpha", "Наименование": "Разработка Сайта", "Бюджет": 250000 },
    { "id": "proj-beta", "Наименование": "Консалтинг", "Бюджет": 120000 }
  ]
}
```

#### 2. Справочник «Клиенты» (ID: 102)
Этот справочник одновременно является **дочерним** для Проектов и **родителем** для Договоров. К его карточкам прикреплен справочник Договоров (ID: 103) в режиме эксклюзива (`ONE_TO_MANY`).

Посмотрите на строки (`rows`): поле `_ownerContext` хранит **массив объектов**, благодаря чему Клиент *«Иван»* одновременно привязан и к проекту Альфа, и к проекту Бета.

```json
{
  "id": 102,
  "type": "directory",
  "title": "Клиенты",
  "columns": ["Наименование", "Телефон"],
  "columnTypes": { "Наименование": "TEXT", "Телефон": "TEXT" },
  "allowedSubDirectories": [
    { "childDirectoryId": 103, "relationType": "ONE_TO_MANY" }
  ],
  "rows": [
    {
      "id": "client-ivan",
      "Наименование": "Иван Иванов",
      "Телефон": "+7 (999) 111-22-33",
      "_ownerContext": [
        { "directoryId": 101, "rowId": "proj-alpha" },
        { "directoryId": 101, "rowId": "proj-beta" }
      ]
    },
    {
      "id": "client-petr",
      "Наименование": "Петр Петров",
      "Телефон": "+7 (999) 444-55-66",
      "_ownerContext": [
        { "directoryId": 101, "rowId": "proj-alpha" }
      ]
    }
  ]
}
```

#### 3. Справочник «Договоры» (ID: 103)
Строго подчиненный справочник. Посмотрите на строки: его поле `_ownerContext` хранит **одиночный объект** (строго один владелец). Договор №1 намертво закреплен за Иваном.

```json
{
  "id": 103,
  "type": "directory",
  "title": "Договоры",
  "columns": ["Наименование", "Сумма"],
  "columnTypes": { "Наименование": "TEXT", "Сумма": "NUMBER" },
  "allowedSubDirectories": [],
  "rows": [
    {
      "id": "dogovor-001",
      "Наименование": "Дог №101 на Поставку",
      "Сумма": 50000,
      "_ownerContext": { "directoryId": 102, "rowId": "client-ivan" }
    },
    {
      "id": "dogovor-002",
      "Наименование": "Дог №102 на Сервис",
      "Сумма": 15000,
      "_ownerContext": { "directoryId": 102, "rowId": "client-ivan" }
    }
  ]
}
```

## 🛠️ Пошаговый сценарий работы в интерфейсе

### Сценарий 1: Общий пул (N:M) — Клиенты в Проектах
1. Перейдите в справочник **«Проекты»**. Нажмите кнопку **`⚙️ Связи`**.
2. В выпадающем списке напротив справочника *«Клиенты»* выберите режим **`🔗 Общий пул (N:M)`** и сохраните схему.
3. Откройте карточку проекта *«Разработка Сайта»* (двойным кликом). Внизу появится под-вкладка `🗂️ Клиенты (0)`.
4. Нажмите кнопку **`🔗 Привязать из базы`**. Отметьте галочками *Ивана* и *Петра*. Нажмите привязать — они отобразятся в подтаблице проекта.
5. Закройте карточку, откройте соседний проект *«Консалтинг»*. Перейдите во вкладку Клиентов, нажмите **`🔗 Привязать из базы`**. 
6. Система **не напишет**, что свободных записей нет. *Иван* снова доступен для выбора! Привяжите его. Теперь Иван одновременно закреплен за двумя проектами. Живые счетчики на табах покажут актуальное количество связанных строк.

### Сценарий 2: Эксклюзивное подчинение (1:N) — Договоры Клиентов
1. Перейдите в справочник **«Клиенты»**. Нажмите кнопку **`⚙️ Связи`**.
2. Напротив справочника *«Договоры»* выберите режим **`🔒 Подчиненный (1:N)`** и сохраните.
3. Откройте карточку *Ивана*. Перейдите в нижнюю под-вкладку `🗂️ Договоры (0)`.
4. Нажмите кнопку **`+ Создать`**. Заполните карточку: *«Дог №101 на Поставку»*, сумма *50000*. Нажмите сохранить. Договор закрепился за Иваном, счетчик стал `(1)`.
5. Закройте карточку Ивана, откройте карточку *Петра*. Перейдите в Договоры и нажмите **`🔗 Привязать из базы`**.
6. Система выдаст сообщение: *«В базе данных нет свободных записей для привязки»*. Почему? Потому что созданный договор №101 эксклюзивно принадлежит Ивану и скрыт от других клиентов во избежание дебиторских ошибок. Чтобы привязать договор к Петру, его нужно сначала отвязать (нажать `✕`) в карточке Ивана.

---

## 🛡️ Безопасность и каскадная очистка данных
Система содержит встроенный механизм **Cascade Delete**. Если вы удалите карточку Клиента *Ивана*, главный оркестратор приложения автоматически просканирует метаданные, найдет подчиненный справочник «Договоры» (так как тип связи был `1:N`) и **полностью сотрет** из базы данных все договоры Ивана, предотвращая появление скрытых записей-сирот.
